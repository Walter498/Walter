# 栗子漫画源（lizimh）

由 Walter498 维护，适用于 Venera / Venera-Max 的漫画源。当前版本 **v2.33.8**。

## 安装 / 更新

在 App 的漫画源管理中更新栗子源，或使用以下地址导入：

```
https://raw.githubusercontent.com/Walter498/Walter/main/lizimh.js
```

只更新源即可，不需要重新编译或安装 App。更新后若还显示旧数据，请刷新首页；重启 App 可重新初始化源。

## 2026-10-02：修复 API 全部 403

官方 App 仍使用 `http://ai.xajtl.com`，但 API 请求需要有效 `lzsign` 和时间戳 `t`。旧源未带签名，因此首页、搜索、分类、排行、详情均被拒绝。不是域名整体失效，也不能通过更换 UA 或改用 HTTPS 解决。

本次修复：

- 按官方接口路径与当前 Unix 秒时间戳生成签名，每次请求重新计算，不写死抓包值。
- 首页、搜索、分类、排行、详情、配置、API 测速及官方章节 v3 统一加签。
- 保留原查询参数，补齐首页 / 配置的官方公开参数。
- 请求错误显示接口路径及 HTTP 错误，避免所有网络错误都只变成「探索页加载失败」。
- JWT 仍由用户在源设置填写，支持纯 JWT、`Jwt:` 前缀及 `Bearer` 前缀；任何用户凭证都没有内嵌到代码。
- 修复源重启后序号到章节 ID 的映射，以及下一章预取误用章节序号的问题。

实测（2026-10-02）：新生成签名的 health、home/data、configv2、search/full、category/list、rank/list、detail 共 **7/7 返回有效 JSON 200**。源首页得到 8 个区块；魔皇大管家 936 章的顺序与真实章节 ID 回归测试通过。使用用户自己提供的授权，单次章节 v3 请求得到 118 张官方顺序图片。记录只表示测试时结果，服务端变化或账号额度不足仍可能导致请求失败。

## 主要能力

- 官方章节顺序：详情章节点以阅读序号为 key，避免 JS 对整数 ID key 自动排序导致补更章节错位。
- 章节图片优先使用官方 v3 返回的 `pics`。需要自己的登录凭证，受站方登录、阅读时间和账号额度限制；没有凭证则沿用图片目录推导。
- 图片多线路、失败换线、页数探测、第一张存在页检查。
- API 延迟 / 图片下载速度分别测试，弹窗可以重新测试，不自动改变手动选好的线路。
- 源的修改独立于 App 通用功能，其他源不套用栗子签名或参数协议。

## 凭证与限制

请只使用自己的授权凭证，并在设备上的源设置中填写。不要把 JWT 放入公开仓库、截图或分享链接。公开元数据接口不需要 JWT；JWT 不能替代请求签名。官方章节接口的账户限制不会被绕过。

## 验证

```sh
node --check lizimh.js
node tools/signature_smoke.js
node tools/signature_smoke.js --live
node harness_smoke.js 57229
```

可选 `LIZI_CAPTURE_PATH` 指向自己提供的抓包文件，离线对照签名。测试不打印请求签名或登录凭证；抓包文件不应提交到仓库。
